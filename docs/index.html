shadow-ink documentation

Transfer files through terminal output, with persistent checkpoints and SHA-256 verification.

Start with one command. The default backend reads Base64 lines from a local tmux pipe. Sampled text and QR playback use the same recovery protocol.

shadow-ink server-a /home/user/results.bin

This guide documents CLI v{{VERSION}} on macOS and Linux. 中文说明 · Interactive demo

Installation

Install shadow-ink on both machines. The receiver needs tmux, SSH and Python 3.9+. The remote sender needs Python 3.9+ and working non-interactive SSH authentication.

MachineRelease package
macOSshadow-ink-*-macos-universal2.tar.gz
Linux receivershadow-ink-*-linux-x86_64.tar.gz
Linux sendershadow-ink-send-*-linux-{x86_64,aarch64}.tar.gz

Download the latest release, verify its SHA256SUMS, and extract it. Inside the extracted package:

mkdir -p ~/.local/bin
install -m 755 ./shadow-ink ~/.local/bin/shadow-ink
# Add ~/.local/bin to PATH if it is not already present.
shadow-ink --version
Build from source

Requires Rust 1.88+, a C/C++ compiler and CMake.

cargo build --release --locked
# Sender-only build for the remote machine:
cargo build --release --locked --no-default-features --target-dir target/sender

Quick start

server-a is a hostname or an alias from your existing ~/.ssh/config.

# A file:
shadow-ink server-a /home/user/results.bin

# A directory and a chosen local destination:
shadow-ink server-a '/home/user/experiment data' -o ./received

# The SERVER:PATH form also works:
shadow-ink server-a:/home/user/results.bin

Downloads default to ~/Downloads/from-server-a/. Directories arrive as .tar archives; extraction is left to you. Existing same-name files with different content are preserved, with the new file placed under transfer-ID/.

The one-command entry point creates its own local tmux canvas, prepares a remote snapshot, receives the file and verifies its SHA-256. It closes only the sessions it created.

Choose a transport

BackendChannelUse
pipeBase64 lines via pipe-paneDefault; reads the original terminal output stream.
textComplete lines via capture-paneSamples a dedicated 320×120 text canvas.
qrQR frames in a tmux paneVisual playback with selectable QR profiles.
shadow-ink server-a /path/file --backend pipe
shadow-ink server-a /path/file --backend text
shadow-ink server-a /path/file --backend qr --speed safe

All three retain Reed–Solomon recovery, CRC32C and SHA-256 checks. The CLI name pipe corresponds to the lower-level sender backend text-stream.

QR profiles: safe, balanced, fast, turbo and auto. Auto uses a valid local recommendation or falls back to safe. --speed selects QR; use --fps for text and pipe. Configured refresh rates and demo timing are not measured throughput.

Resume & snapshots

# Rerun the same command to resume an unfinished transfer:
shadow-ink server-a /path/file -o ./received

# Explicitly require the saved snapshot:
shadow-ink server-a /path/file -o ./received --resume

# Capture the current source instead, keeping previous state:
shadow-ink server-a /path/file -o ./received --fresh

Keep the same host, source path and destination. A resumed job restores the original snapshot even if the source has changed. --resume fails when no local record exists and cannot be combined with --fresh.

The receiver rechecks cached shards and completed groups before asking for missing or damaged groups. It publishes output only after the original file's SHA-256 matches.

LocationPurpose
~/.local/state/shadow-ink-get/Local checkpoint, shards and logs; respects $XDG_STATE_HOME.
~/.cache/shadow-ink-get/Remote immutable snapshots.

Keep both locations to resume. Caches are not automatically deleted.

Manual reception

If you already have an SSH pane in local tmux, prepare a bundle on the remote machine, then play it into that pane.

Remote terminal

shadow-ink prepare results.bin --compress auto --symbol-bytes 224 --out results.tqtx
shadow-ink send results.tqtx --qr-version 12 --ecc M --fps 3 --loop

Local terminal

shadow-ink panes
# Replace %0 with the pane running the remote sender.
shadow-ink recv --source tmux:%0 --capture-fps 20 --output ./received --state ./rx-state

Keep the prepared bundle and receiver state to resume. For a saved local QR video, use --source video:./recording.mp4; video input also requires FFmpeg. Manual recv defaults to a 1 GiB limit.

Troubleshooting

Remote sender is missing
Install the current binary as shadow-ink on the remote PATH or at ~/.local/bin/shadow-ink. Both ends must use the new command name.
No saved snapshot
Run the command without --resume first. If a remote snapshot has been removed, use --fresh to start a new one.
QR does not fit
Use --speed safe first. Manual QR V12-M needs at least 74×40 usable cells including its markers. Inspect geometry with shadow-ink doctor.
A transfer times out
Repeat the same command to resume. Keep its local checkpoint and remote snapshot; allow enough time for SSH startup before expecting useful progress.

For a bug report, include the version, OS, backend and exact command. Remove private paths and content from shared logs. Report an issue.
